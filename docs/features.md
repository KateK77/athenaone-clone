# Feature inventory

Status is relative to the complete original brief. **Implemented** applies to the specifically named behavior, not every possible enterprise variation. **Partial** explicitly identifies significant unmet parts of that module. All URLs are relative to the application origin; `{id}` denotes a record ID. Tests refer to `tests/test_workflows.py` (backend) and `tests/test_browser.py` (browser).

| Module | Feature | Status | URL | Executed coverage | Known limitations |
|---|---|---|---|---|---|
| Identity | Nine role-based logins, hashed passwords, sessions, POST logout | Implemented | `/login/` | All demo login, invalid login, CSRF, browser sign-in | No MFA or password-reset delivery |
| Authorization | Server-side roles, patient ownership, physician assignment, department intake scope | Implemented | All authenticated routes | Role restrictions, direct URL/POST isolation, scoped form choices | Single practice, not tenant isolation |
| Dashboard | Database-derived role-aware visit, task and billing summaries | Partial | `/dashboard/` | All role dashboards, browser screenshot | Compact card set; not every role-specific metric in brief |
| Patients | Registration, demographics, unique MRN, duplicate check, search/filter/sort/pagination | Implemented | `/records/patients/` | Registration, duplicates, DOB validation, search/pagination, browser journey | Duplicate similarity is exact name/DOB, not fuzzy matching |
| Chart | Summary, encounters, problems, medications, allergies, history, vitals, results, appointments | Implemented | `/patients/{id}/` | Scope checks, chart browser tabs, fixture relationships | Text-based history and documents |
| Documents/immunizations | Typed history entries | Partial | `/records/history/` | Form/detail render coverage | No binary files, scanning, structured vaccine records |
| Scheduling | Day/provider, week, department calendar; create/reschedule; overlap/availability checks | Implemented | `/schedule/` | Conflict, adjacent-slot, cancelled-slot and availability tests; browser booking | No drag/drop, rooms, holidays or recurring schedules |
| Scheduling lifecycle | Confirm, arrive, check in, room, begin, complete, check out, cancel/no-show | Partial | `/records/schedule/{id}/` | Transition, role and full browser journey tests | Rescheduling is an audit event rather than separate Rescheduled state |
| Waitlist | Enrollment, first-fit matching, booking, simulated notification | Implemented | `/records/waitlist/` | Backend matching/booking and form coverage | 30-minute matching, 90-day bound; no actual messaging |
| Front desk | Five required verification gates, copay and clinical worklist handoff | Implemented | `/appointments/{id}/check-in/` | Incomplete rollback, copay, encounter/task creation, browser journey | Intake forms represented by confirmation flag |
| Nursing | Intake, medication/allergy/history review, vital signs, calculated BMI | Implemented | `/encounters/{id}/intake/` | Range validation, BMI, browser intake | No structured screening questionnaires |
| Encounters | SOAP drafts, versions, preview, template prompts, copy-forward, signing, addenda, close | Partial | `/encounters/{id}/` | Version conflict, missing fields/ack/reconciliation, immutability, browser sign-off | No autosave; Ready for Sign-off is checklist-only; limited macros |
| Diagnoses | Curated ICD examples, primary/secondary encounter diagnoses, longitudinal status | Implemented | `/records/problems/` | Cross-patient rejection, sign-off requirements, charge linkage | Small catalog, signed coding locked |
| Medications | Draft/sign/discontinue, dose/route/frequency/quantity/pharmacy, renewal requests | Partial | `/records/medications/` | Warning and acknowledgment tests, portal renewal | Free-text catalog fields; no real prescribing or complete interaction engine |
| Orders | Linked diagnosis, category, priority, sign/process/complete/cancel/fail, tasks | Implemented | `/records/orders/` | Order/task lifecycle, cross-patient validation | No real downstream interface |
| Laboratory | Enter, publish, review, release result; portal privacy | Partial | `/records/results/` | Result lifecycle, release gate, unreleased export/portal denial | One component per order; no specimen accession or full panels |
| Insurance | Coverage records and deterministic eligibility simulation | Partial | `/records/insurance/` | Check-in active coverage, scrub dates/member checks, browser verify | No actual payer, cost-sharing benefit engine or separate exception queue |
| Charge capture | Signed-encounter charges, diagnosis/procedure linkage, approval, duplicate protection | Implemented | `/records/charges/` | Browser coding, scrub checks, model constraint tests | Curated codes; no automatic coding inference |
| Claims | Generate, scrub, review, validate, submit, accept, adjudicate, pay, close | Implemented | `/records/claims/` | Full workflow, revalidation, duplicates, missing authorization, browser settlement | Local deterministic simulator only; one claim per encounter |
| Denials | Queue, reason/category, appeal, due date, correction and resubmission | Partial | `/records/denials/` | Denial recovery test and browser appeal | No full appeal document/assignment/analytics subsystem |
| Authorizations | Request, submit, review, ask for info, approve/deny, billing gate | Partial | `/records/authorizations/` | Missing authorization blocks claim; state tests | Text support only; no background expiry update |
| Payments | Balance checks, copay allocation, duplicate form protection, receipt | Implemented | `/claims/{id}/payment/` | Partial/full/overpayment/negative/precision/ownership/duplicate tests; browser receipt | No refunds, contractual adjustments or multi-claim allocation |
| Statements | Portal balances and transaction lists | Partial | `/portal/` | Portal rendering and payment tests | No statement generation/distribution engine |
| Portal | Own visits, summaries, released results, medications, messages, balances | Implemented | `/portal/` | Ownership tests and browser portal | No patient enrollment, proxy access or identity verification |
| Engagement | Appointment requests, pre-check-in, cancellations, renewal requests, contact updates | Implemented | `/portal/`, `/records/requests/` | Request/task tests, browser requests, booking checks | Local task notifications only |
| Messaging | Patient/staff threads, replies, timestamps, read/unread, inbox tasks | Implemented | `/records/messages/` | Isolation, task creation, browser persistent conversation | No attachments or external notifications |
| Inbox | Role-scoped tasks, assignment, reassignment, priority, due date, completion/filter/search | Implemented | `/records/tasks/` | Scope, lifecycle task and completion tests | No multi-step configurable workflow engine |
| AI summary/prep | Chart facts, recent history/results/orders, limited workflow reminders | Implemented | `/ai/` | Render, assigned chart scope, browser navigation | Deterministic extraction, not a clinical reasoning model |
| AI scribe | Transcript → structured draft → explicit reviewed application | Implemented | `/encounters/{id}/` | Draft approval/no autosign/XSS tests, browser draft preview | No transcription; plan must be clinician-completed |
| AI optional integrations | Live LLM, diagnosis/order suggestions, coding assistance | Missing | — | Not run; not implemented | No external model/API keys used |
| Analytics | Date/provider/department metrics, status charts, A/R, diagnoses, utilization, payment trend, CSV | Partial | `/reports/` | Rendering, CSV, data-based computations | Current balances, not historical ledger; limited utilization assumptions |
| Administration | Staff accounts/roles, providers/hours, departments, visit types | Implemented | `/administration/` | Role rejection, forms, self-lockout protection | Practice identity fixed; no full enterprise settings catalog |
| Audit | Actor/time/entity/state history, immutable UI log | Partial | `/records/audit/` | Transition audit, record audit, model coverage | Not cryptographically tamper-proof; not every invalid form logged |
| Reset | Confirmed, administrator-only, local-demo-only reset with event | Implemented | `/administration/reset/` | Disabled/environment guard tests; local command verification | Disabled in production and PostgreSQL |
| Interoperability | Nine read-only FHIR-inspired JSON types with ownership checks | Partial | `/fhir/{resource}/{id}/` | All nine exports, cross-patient/unreleased denial | No conformance, OAuth, bundles, search or import |
| Deployment | PostgreSQL-only production config, health, static assets, Render Blueprint, CI | Partial | `/health/`, `render.yaml` | Local health/system checks and live schema validation | Cloud runtime and remote CI results reported separately |
| CUA evaluation | Independent Computer Use Agent evaluation | Missing | — | Not performed | Playwright is not a substitute |

The original specification remains the authority for evaluating omissions. See `limitations.md` for additional details and `testing.md` for actual executed test totals.
